# 성취기준 조회와 검증

2022 개정 교육과정 성취기준을 찾고, 그 원문을 어느 정도까지 믿을 수 있는지 표시하는 절차다.

## 1. 먼저 확인할 것

| 항목 | 왜 |
|---|---|
| **사용 학년도** | 2022 개정 교육과정은 학년별로 시행 시점이 다르다(예: 중3·고3은 2027-03-01, 2026-1호 고시의 초1·2 개정 내용은 2028-03-01). 저장소에 있다고 올해 수업에 자동 적용하지 않는다 |
| 학교급·학년·과목 | 서버 분기와 과목 필터에 필요. 중·고는 정확한 과목명(공통과목/선택과목 구분) |
| 특성화고 여부 | 보통교과(국어·수학 등)는 중등 서버, 전문교과는 직업 서버 |
| 교사가 이미 원문을 가지고 있는지 | 있으면 조회는 확인용. 교사 원문을 우선 기록 |
| 판본에 따른 용어 | 2022 개정은 성취수준(A–E)·학점(고), 2015 개정은 평가기준(상·중·하)·단위. 출력 용어를 교사 학년의 판본에 맞춘다 |

## 2. 사용할 도구

교사 환경에 연결된 MCP 서버 세 종류. **먼저 현재 세션에 어떤 도구가 실제로 연결되어 있는지 확인**하고, 없으면 4절로 간다. 도구 이름과 인자는 아래 저장소 버전 기준이며, 연결된 서버의 실제 스키마가 다르면 그것을 따른다.

| 서버 | 저장소 | 대상 |
|---|---|---|
| 초등 | `taehyeonglim/korean-elementary-learning-map-mcp` | 초1–6, 11교과 |
| 중등 | `raphysicst-create/korean-secondary-learning-map-mcp` | 중학교·고등학교 보통교과 |
| 직업 | `raphysicst-create/korean-vocational-learning-map-mcp` | 특성화고·마이스터고 전문교과 18계열 |

### 조회 순서

**초등**
1. `list_curricula`: 실제 교과명 확인
2. `search_standards`(query, subject, gradeBand `1-2|3-4|5-6`, domain) 또는 `search_standard_text`(원문 키워드)
3. `get_standard`(code): 전체 레코드와 원문

**중·고 보통교과**
1. `list_curricula`(schoolLevel `middle|high`, subjectGroup): 과목명 확인
2. `search_standards`(query, subject, schoolLevel, gradeBand `7-9|10|10-12`, domain) 또는 `search_standard_text`
3. `get_standard`(code, **subject**): **같은 코드를 두 과목이 공유하는 경우가 있으므로 과목명을 함께 준다**

**특성화고 전문교과**
1. `list_major_fields`: 계열 확인
2. `list_curricula`(majorField): 과목 확인
3. `search_standard_text`(query, subject, majorField) 또는 `search_standards`
4. `get_standard`(code, subject, majorField)

공통: 검색 `limit` 상한은 50이며 페이지 인자가 없다. **50건이 나왔다고 전체가 아니다.** 필터를 좁혀 다시 검색한다.

## 3. 반환값을 다루는 규칙

MCP가 돌려주는 값을 그대로 "검증된 현행 원문"으로 취급하지 않는다. 조사에서 실제로 발견된 문제:

- 초등 데이터 일부 성취기준 본문에 내용체계표의 다른 열이 섞여 있었다.
- 중등 저장소는 최신 일부개정 미반영을 스스로 고지한다.
- 중등에 다른 과목이 같은 코드를 쓰는 사례가 있다.
- `summary`, 관찰 증거, 평가 발문 등은 **기계 파생** 항목일 수 있다. 이것을 평가요소로 복사하지 않는다. 공식 본문(`officialText`)과 교사의 해석을 우선한다.
- 성취기준 해설·적용 시 고려사항·평가 방향은 MCP 본문에 충분하지 않다. 중요한 기준은 교사에게 해당 교과 교육과정 문서(NCIC 고시 별책)의 해설 절을 확인하도록 안내하거나, 교사가 제공한 해설을 쓴다.
- **성취기준별 성취수준**(2022 개정 중·고, 교육부·평가원 자료)도 MCP에 없다. 교사가 제공하면 수준 기술의 출발점으로 쓴다. 성취기준 전체에 대한 기술이므로 이번 과제의 요소에 맞게 좁힌다.

따라서 성취기준을 기록할 때 **상태**를 함께 적는다.

| 상태 | 뜻 |
|---|---|
| `사용자 제공` | 교사가 준 원문. 출처 미확인이면 그렇게 표시 |
| `저장소 수록` | MCP에서 조회했으나 공식 문서와 대조하지 않음 |
| `공식 대조 완료` | 교사 또는 스킬이 고시 문서와 대조함 |
| `충돌` | MCP 본문과 교사 원문(또는 공식 문서)이 다름. 둘 다 보존하고 교사에게 확인 |
| `미확인` | 코드·본문을 찾지 못함. 만들어 내지 않음 |

적용 연도는 별도 표시: `적용 확인` / `적용 미확인`. 공식 본문 대조가 끝났어도 올해 그 학년에 적용되는지는 별개다.

출력에 남길 최소 정보: 서버(또는 사용자 제공), 과목, 코드, 원문, 상태, 적용 연도 상태. 검색 스니펫으로 원문을 확정하지 않는다.

## 4. MCP가 없거나 실패할 때

- 교사가 준 성취기준 원문으로 계속 진행한다. 상태를 `사용자 제공`으로 적는다.
- 교사에게 코드와 원문을 요청한다. 없으면 "성취기준 원문 미확인"으로 표시하고 과제·목표 중심으로 설계한다.
- **코드를 추측해서 만들지 않는다.** "[9사03-02]일 것 같다"는 말을 하지 않는다.
- 스킬 설치가 MCP 연결을 보장하지 않는다고 안내한다.

## 5. 성취기준 문장을 평가요소로 바꿀 때

- 한 문장 안의 지식·이해 / 과정·기능 / 가치·태도를 **기계적으로 요소 셋으로 만들지 않는다.** 이번 과제에서 실제로 가르치고 관찰할 부분을 교사와 고른다.
- 성취기준이 요구하는 사고(설명, 추론, 정당화, 설계)와 과제가 요구하는 사고가 다르면 정렬표에서 드러낸다. 판단이 필요하면 `dok.md`.
- 여러 성취기준을 한 과제로 평가하면 요소가 어느 기준에 해당하는지 표시한다. 다른 기준에 속한 요소는 배점을 합치지 않고 따로 보고할 수 있다.
- 중·고 평가계획은 수행평가 영역 2개 이상이 서로 다른 성취기준을 다루기를 요구하는 경우가 많다. 같은 성취기준·같은 시기의 두 영역은 하나로 통합을 제안한다(`school-review.md`).

## 6. 권리

세 저장소 코드는 MIT이며, 성취기준 원문은 각 저장소가 공공저작물·고시 원문 근거를 제시한다. 이는 저장소의 판단이다. 루브릭 산출물에 성취기준 원문을 인용하는 것은 문제없으나, 저장소의 요약·파생 항목을 재배포할 때는 출처를 남긴다.
