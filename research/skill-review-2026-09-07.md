# Rubric Creator 검토와 추가 도서 활용 제안

검토일: 2026-09-07. 대상: `pblsketch/rubric-creator`, 커밋 `e4cc098e15b40bbd196b20f2ab92afb1e0e807fb`.

이 문서는 개편 전 상태의 검토 기록이다. 이후 반영 내용과 검증 범위는 [개편 검증 기록](validation/release-check-2026-09-07.md)을 참고한다. 아래 파일 행 번호와 수치는 검토 당시 버전을 가리킨다.

## 1. 판단

**교육적 설계와 스킬 구조의 기반은 좋다. 다만 공개 사례의 정합성 오류를 먼저 고치고, 형성적 활용과 배점 해석을 보강할 필요가 있다.** 현재 근거로 말할 수 있는 것은 ‘이론에 근거한 설계·개선 절차와 문서 적용 사례가 있다’는 수준이다. 여러 환경에서의 모델 행동, 학생의 학습 효과, 채점자 간 일치가 검증됐다는 뜻은 아니다.

두 책은 모두 도움이 된다. 특히 *Advancing Formative Assessment in Every Classroom*은 학생이 루브릭을 이해하고 수정에 사용하는 절차를, *How to Use Grading to Improve Learning*은 연습과 성적 반영의 구분 및 점수의 의미를 강화한다. 기존 책과 겹치는 내용도 많으므로 모든 내용을 새 기능으로 추가하기보다, 현재 지침에서 빠진 적용 조건과 후속 행동을 채우는 편이 적절하다.

이 문서는 검토와 제안이다. 스킬 본체·배포 ZIP·공개 README를 수정하거나 GitHub에 게시하지 않았다.

## 2. 확인 범위와 증거

| 확인 항목 | 이번 결과 | 의미와 한계 |
|---|---|---|
| Git 상태 | 검토 시작 시 `main`, 작업 트리 깨끗함 | 기존 미커밋 변경 없음 |
| 공개본 일치 | 로컬 HEAD와 GitHub API의 `main` SHA 일치 | 공개한 커밋을 검토함 |
| 스킬 구조 | `SKILL.md`, 참고 파일 8개, 설치 안내·메타데이터 검토 | 진입점 128행, 조건별 참고 파일 분리 |
| 형식 검증 | `python -X utf8 .../quick_validate.py rubric-creator` → `Skill is valid!` | 형식·이름 검증이며 교육적 타당성 증명은 아님 |
| ZIP | 파일 11개, 본체 파일과 바이트 불일치 0개 | 배포본과 본체 동기화 확인 |
| 참고 경로 | 검사한 내부 Markdown 파일 참조의 누락 0개 | 모든 외부 URL의 정상 동작을 검사한 것은 아님 |
| 도서 취급 | 도서 PDF는 Git 추적 목록·배포 ZIP에 없음 | 로컬 참고 자료로 사용됨 |
| 문서 사례 | 국·영·수·사·과 5건과 검증 요약 검토 | 이번 검토에서 학교 원본·비공개 대응표·MCP 결과를 재수집하지 않음 |
| 점수 경계 검사 | 국어 개선표의 가능한 합계를 전수 열거 | 아래 R1의 불일치 확인 |
| 도서 확인 | 추가 두 책의 전체 텍스트 추출, 목차 및 관련 장 선별 정독 | 290쪽·246쪽 PDF; 전권 완독이나 모든 인용 연구 재검증은 아님 |
| 시각 대조 | 형성평가 PDF 46쪽, 성적평가 PDF 140쪽, 기존 루브릭 PDF 209쪽 | 텍스트 추출로 빠지는 도표를 렌더링해 확인 |

Windows 기본 문자 인코딩으로 읽을 때 깨짐이 있어 UTF-8로 다시 읽었다. 형식 검증도 UTF-8 모드에서 통과했다. 이는 이번 검사 도구의 실행 조건이며 스킬 파일이 손상됐다는 증거는 아니다.

## 3. 잘 만들어진 부분

- **학습목표 → 수행 증거 → 평가요소 → 수준 기술 → 학생용 기준**의 연결이 명확하다. 표부터 생성하지 않고 무엇을 평가하는지 확인하게 한다. 근거: `rubric-creator/SKILL.md` 7–16행, 64–91행.
- **모드와 자료를 분리했다.** 기존 표 개선, 과제 재설계, 교육과정 조회, DOK 검토를 필요에 따라 읽는다. 단순한 요청에도 모든 이론을 불러오게 만들지 않았다.
- **자주 생기는 루브릭 오류를 실행 규칙으로 바꿨다.** 개수 세기, 평가 축 변경, 형식·순응의 성취 대체, 근거 없는 기대 이상 조건을 점검한다. 수치·안전이 실제 목표인 예외도 둔다.
- **교육과정 확인의 한계를 표시한다.** 사용자 제공·저장소 수록·공식 대조 완료를 구분하고, 과목과 적용 연도를 별도로 확인하며, MCP가 없어도 제공된 원문으로 진행한다. 이번에는 이 절차의 설계를 검토했으며 개별 고시와 MCP의 현재 정확성을 인증하지 않았다.
- **학생을 자동 채점하는 기능과 기준을 설계하는 기능을 구분했다.** 실제 학생 작업으로 구별력을 살피더라도 출력은 루브릭 진단으로 제한한다.
- **공개 문서에 검증의 한계를 적었다.** 실제 학생 작업과 교사 인터뷰가 없었다는 점을 숨기지 않는다. 다만 일부 세부 성공 주장은 아래처럼 수정이 필요하다.

## 4. 수정 우선순위

### R1. 우선 수정: 국어 사례는 기존 점수 분포를 보존하지 않았다

위치: `research/validation/case-1-korean.md` 44행, 61–68행, 86행.

원본의 제출물 점수는 `13, 15, 17, 19, 20`이고 이를 유지한다고 명시했다. 개선표의 세 요소는 각각 `[2,3,4]`, `[5,6,7,8]`, `[5,6,7,8]`이다. 숫자가 있는 칸의 모든 조합을 합산하면 다음과 같다.

```text
원본:       [13, 15, 17, 19, 20]
개선표 합계: [12, 13, 14, 15, 16, 17, 18, 19, 20]
추가된 값:   [12, 14, 16, 18]
```

총점 20점은 같지만 최저점과 가능한 점수 단계가 달라졌다. ‘학교의 압축 분포 유지’는 현재 표로 입증되지 않는다. 요소 1의 ‘시작’ 칸이 ‘해당 없음’이어서 논제·입장을 전혀 드러내지 못한 제출물의 처리도 불명확하다.

**제안:** 질적 수준 기술과 최종 점수 대응을 분리한다. 기존 점수 체계를 유지하려면 수준 조합을 기존 점수에 연결하는 명시적 판단 규칙이 필요하다. 유지가 어렵다면 구조 변경 제안이라고 표시한다. 최대점뿐 아니라 최저점·가능한 점수 집합·결측 처리를 확인해야 한다.

### R2. 우선 수정: 본체의 최고 수준 예시에 목표 확장 조건이 빠졌다

위치: `rubric-creator/references/rubric-principles.md` 64행, 121–127행.

예시 목표는 ‘자료를 근거로 지역 문제의 원인을 설명한다’인데, 최고 칸은 ‘자료의 한계나 다른 해석 가능성까지’ 요구한다. 그 능력이 이번 수업목표와 가르친 내용에 포함됐는지 제시하지 않고 ‘새 능력이 아니다’라고 단정한다.

한계 검토가 부적절하다는 뜻은 아니다. **학습목표와 수업 기회의 확인 없이 최고점 조건으로 넣는 것이 문제**다. 이 예시를 따라가면 AI가 최고 칸마다 반론·한계·추가 탐구를 자동으로 붙일 수 있다.

**제안:** 같은 목표 안에서 자료–설명의 연결이 얼마나 정확하고 일관된지로 수준을 기술한다. 한계 검토가 목표라면 정렬표·수업 기회·학생 안내에 먼저 포함한다. 도달 자체가 최고 모습인 요소에는 위 칸을 억지로 만들지 않는다.

### R3. 보완: ‘중앙값 권장’에 판단 조건과 경계 처리 절차를 붙인다

위치: `rubric-creator/SKILL.md` 91행, `references/rubric-principles.md` 85–95행.

중앙값 권장 자체는 기존 책에 근거가 있다. 한국어판 PDF 204–206쪽에서 요소 점수 종합을 다루며, PDF 209쪽의 의사결정 나무는 성취기준별 분류와 시간에 따른 변화도 고려한다. 따라서 ‘중앙값은 잘못’이라는 수정은 부당하다.

현재 지침에는 다음 조건이 충분히 드러나지 않는다.

- 한 과제의 여러 요소를 요약하는 것과 같은 성취기준을 여러 시점에 평가한 증거를 종합하는 것의 차이.
- 같은 수준 번호가 같은 성취 의미를 갖는지 확인하는 절차.
- 중앙 두 범주가 다를 때 임의의 중간 등급을 만들지 않는 처리.
- 같은 성취기준에서 지속적 향상·하락이 보일 때 계산 결과를 재검토하는 절차.
- 최근 자료라도 다른 성취기준을 측정했다면 이전 자료를 대체하지 않는 조건.

**제안:** 성적 반영 방식을 요청한 경우에만 읽는 `references/grading-use.md`로 상세 절차를 분리한다. 학교 규정과 기존 점수 체계 안에서 설계안을 제시하고, 실제 학생의 성적 계산·확정 기능으로 확장하지 않는다. 추가 책 G의 PDF 138–148쪽이 직접적인 보완 근거다.

### R4. 보완: 공개 예시가 성찰을 ‘바꾼 흔적’으로 좁힐 수 있다

위치: `research/validation/case-2-english.md` 63행.

‘과정 성찰과 수정’ 최고 수준은 실제 변경이 최종 자료에 반영되어야 한다. 처음부터 목표를 충족한 부분을 근거를 들어 유지하거나, 동료 제안이 기준과 맞지 않아 받아들이지 않은 경우의 성공 경로가 없다. 실제 변화가 적다는 이유로 성찰의 질이 낮다고 읽힐 수 있다.

**제안:** 기준과 작업 증거를 비교한 판단, 변경 또는 유지의 이유, 그 판단의 적절성을 본다. 성찰·수정 자체가 이번 학습목표일 때만 학업 평가요소로 포함한다. 학생용 형성평가 기록은 교사의 성적 산정 자료에 자동 합산하지 않는다. 추가 책 F의 PDF 115쪽은 동료 제안의 채택을 학생이 결정하고 기준으로 이유를 설명하게 한다.

### R5. 보완: ‘모든 과제에 설명 필수’를 목표에 따른 조건으로 바꾼다

위치: `rubric-creator/references/task-design.md` 31행과 `references/subject-guidance.md`의 예술·체육·직업 교과 지침.

과제 재설계에서는 설명을 항상 포함하라고 하는 반면 교과별 지침은 설명 글로 실제 수행을 대체하지 않도록 한다. 기능·표현·안전 수행이 목표인 요청에 재설계 모드가 걸리면 목표 밖의 언어 부담이 붙을 수 있다.

**제안:** 이해·추론·설계 판단이 목표라면 그 이유를 드러내는 증거를 확보한다. 기능 수행 자체가 목표라면 실제 수행 관찰을 우선한다. 설명은 필요한 경우에 구술·시연·표시 등 목표에 적합한 방식으로 받는다. 자료 부족만으로 이해가 없다고 단정하지 않는다.

### R6. 검증 보고를 정리하고 실제 행동 검증을 확장한다

위치: `research/validation/README.md` 28행, 42–43행, `README.md` 검증 소개.

현재 5건은 기존 표 개선 사례다. 새 루브릭 생성, GRASPS 재설계, 학생용 형성적 활용, 채점 요청 경계, 서로 다른 실행 환경의 행동을 확인하는 검증과는 범위가 다르다. 검증 문서도 학생 작업을 통한 경계 사례 점검은 미실시라고 명시한다.

또한 검증 요약의 ‘다섯 사례 모두 개수 세기’는 공개된 수학 원본표의 ‘오류 없음/있음/부분/없음’ 서술과 맞지 않는다. ‘모든 개선안이 학교 양식 안에 들어간다’는 주장도 R1을 해결하기 전에는 유지하기 어렵다.

**제안:** 문서 사례 적용 / 새 모델 실행 / 교실 활용 / 교사 간 기준 조정의 증거를 구분한다. 현재 없는 행동 검증을 수행한 것으로 쓰지 않는다. 7절의 입력과 통과 조건으로 후속 검증을 시작할 수 있다.

추가 편집 점검: 영어 사례의 원본은 7장 미달 감점인데 개선 체크리스트는 ‘7장 이내’로 바뀌었다(해당 파일 24행과 68행). ‘최소·고정·최대’ 조건의 변경 여부를 명시해야 한다. 몇몇 사례 표의 열 제목 ‘원문(공식)’도 상태가 ‘저장소 수록’인 행까지 공식 대조 완료로 오해하게 할 수 있어 ‘성취기준 본문’처럼 중립적으로 바꾸는 편이 낫다.

## 5. 추가 두 책에서 가져올 내용

쪽수는 모두 **현재 로컬 PDF 뷰어의 1부터 세는 페이지**다. 전자책을 PDF로 만든 파일이므로 종이책 쪽수와 같다고 간주하면 안 된다. 아래 제안은 책의 표·사례를 복제한 것이 아니라 현재 스킬에 맞춘 재구성이다.

### F. Advancing Formative Assessment in Every Classroom

|---|---|---|
| 온전한 학습목표: 목표 진술·한 차시 분량의 내용·이해를 드러내는 수행·성공 기준을 함께 설계. 2장, PDF 43–47쪽, 그림 2.1 | 성취기준–과제–평가요소 정렬 | 학습 활용 요청 시 단원 전체 루브릭에서 ‘이번 차시에 사용할 요소’를 골라 목표·활동·관찰 증거로 연결 |
| 기준을 나누어 주는 것만으로 이해가 생기지 않음. 2장, PDF 51–64쪽 | 자기 말로 설명, 예시 비교, 공동 개발 | 학생의 기준 해석을 확인하고 오해가 있으면 교사가 다시 설명하는 절차. 실제 자료가 없으면 이해 확인 완료라고 쓰지 않기 |
| 피드백의 질은 메시지뿐 아니라 학생이 사용하고 학습이 달라졌는지까지 보아야 함. 3장, PDF 80–87쪽 | 관찰 질문·수정 방향·피드백 시점 | 수정 기회와 재확인 방법을 설계 결과에 명시. 같은 과제 수정 또는 다음 유사 과제 적용 중 맥락에 맞게 선택 |
| 자기평가를 먼저 가르치고 동료평가로 확장. 피드백의 질에도 피드백 제공. 4장, PDF 103–106, 111–116쪽 | 근거 칸, 동료의 질문, 자기평가의 성적 비반영 | 자기평가 연습 → 교사의 근거 확인 → 동료평가 규범 → 수정/유지 결정과 이유로 구체화 |
| 목표 설정과 실행: 현재 간격에 맞는 단기 목표, 전략 선택, 결과 점검. 5장, PDF 133–140, 148–155쪽 | 다음에 고칠 한 가지 | 개선 목표·사용할 전략·다시 확인할 증거를 연결. ‘다음에는 더 열심히’로 끝나지 않게 하기 |
| 전략적 질문은 미리 계획하고 응답을 수업 조정에 사용. 6장, PDF 164–172쪽 | 일반적 관찰 질문 | 핵심 요소에 대해 확인할 증거·그 증거를 이끌 질문·반응에 따른 교사 지원을 연결 |

**가장 효과적인 반영 지점은 `learning-use.md`다.** 현재 자기점검과 수정 방향이 있으므로 이 기능이 전혀 없다고 평가하면 안 된다. 부족한 것은 계획된 수정 시간, 학생의 선택, 수정 뒤 증거 확인, 교사의 수업 조정이다.

기본 루브릭 요청에는 활용 시점과 수정 기회 정도만 짧게 붙이고, 상세 양식은 형성평가·수업 활용 요청이 있을 때 제공한다. 모든 요청을 긴 수업 설계 인터뷰로 늘리지 않는다.

### G. How to Use Grading to Improve Learning

정확한 서지: Susan M. Brookhart, *How to Use Grading to Improve Learning*, ASCD, 2017. 사용자가 언급한 ‘Running’은 로컬 파일의 제목상 **Learning**이다. 로컬 표제·판권과 [ASCD 공식 서지 자료](https://files.ascd.org/staticfiles/ascd/pdf/siteASCD/publications/books/HowToUseGradingToImproveLearning.pdf)를 대조했다.

| 책의 논점과 근거 | 현재 이미 있는 것 | 추가할 실행 절차 |
|---|---|---|
| 학습 중 연습·피드백과 성적 반영용 평가의 구분. 3장 PDF 61–62쪽, 4장 PDF 86, 92–94쪽 | 배점은 마지막, 자기평가는 성적에 직접 반영하지 않음 | 과제 단계마다 목적·증거·피드백/수정 기회·성적 반영 여부를 설계. 초안과 연습을 무조건 최종 점수에 합산하지 않기 |
| 재제출은 충분한 사전 연습을 대체하는 기본 방식이 아님. 3장 PDF 61–62쪽 | 재평가 규정은 학교 기준 | 최초 평가 전 연습, 제출 전 수정, 평가 후 재제출을 구분. 기한·조건은 교사/학교 결정으로 남기기 |
| 루브릭 수준과 보고 점수 사이의 의미를 유지. 4장 PDF 89–91쪽 | 수준 번호와 백분율 구분 | 척도 의미·도달 기준·학교의 점수 대응·총점 및 최저점·경계 처리 확인. 임의의 백분율이나 미국 A–F 기준을 한국에 그대로 적용하지 않기 |
| 같은 성취기준별로 증거를 모으고 여러 방식으로 확인. 5장 전략 9–11, PDF 129–144쪽 | 개별 과제 정렬, 요소별 성취기준 표시 | 반복 사용하는 기준 ID에 시점·과제·증거 종류를 연결. 서로 다른 목표의 점수를 같은 능력의 성장처럼 해석하지 않기 |
| 중앙값·최근 증거·수행 양상·경계 사례의 전문적 판단. 5장 PDF 138–148쪽 | 평균보다 중앙값 권장 | R3의 조건부 절차. 최신 1건만 무조건 채택하거나 가장 높은 결과만 선택하지 않기 |
| 성취와 비성취 요인의 구분, 개인의 성취 증거. 4장 PDF 98–102쪽 | 형식·태도 분리, 개인 증거 확인 | 별도 기록으로 옮긴 태도·제출 항목을 최종 학업 점수에 다시 섞는지 점검. 협력·안전 자체가 정식 학습목표인 예외는 유지 |

이 책의 추가 가치는 ‘점수를 더 잘 계산하는 기능’보다 **점수가 무엇을 뜻해야 하는지, 어떤 증거를 포함해야 하는지 결정하는 절차**에 있다. 성적표 개혁과 학교 전체 정책 변경은 현재 스킬의 필수 범위로 가져오지 않는다.

과정평가를 모두 제외하자는 제안도 아니다. 예를 들어 전략 점검·고쳐쓰기 자체가 목표이고 이를 배울 기회가 제공됐다면 그 수행은 평가 대상이 될 수 있다. 단순한 초안 제출, 수정 횟수, 노력의 양을 목표 능력과 혼동하지 않는 것이 핵심이다.

## 6. 권장하는 최소 개편

1. **공개 사례 정정:** 국어 점수 대응, 영어 변경·유지 판단 및 분량 조건, 검증 요약의 주장 범위부터 바로잡는다. 이 작업이 새 이론 추가보다 우선이다.
2. **본체 예시·조건 정리:** 목표 밖 최고 수준 조건을 제거하거나 조건부로 만들고, 설명 필수 규칙을 학습목표에 따라 분기한다.
3. **`learning-use.md` 확장:** 목표 이해 → 자기 작업의 증거 확인 → 자기평가 → 필요 시 동료평가 → 수정/유지 선택 → 다시 확인 → 교사의 후속 지원을 넣는다. 기존의 학생 개별 채점·피드백 대행 경계는 유지한다.
4. **`grading-use.md` 추가:** 점수 대응과 여러 증거 종합의 조건은 배점 요청 때만 읽도록 분리한다. `SKILL.md`에는 목적 분기와 호출 조건만 남긴다.
5. **출처와 검증 보강:** `sources.md`에 책별 장·로컬 PDF 쪽수와 ‘원저자의 주장 / 스킬용 재구성’을 구분한다. 다음 검증 사례를 추가하고 본체 변경 시 ZIP을 다시 대조한다.

학습 활용 양식은 아래 정도로 확장할 수 있다. 다음은 도서 양식의 복제가 아닌 독자적 빈 틀이다.

| 기준 ID | 현재 작업에서 찾은 증거 | 개선하거나 유지할 점과 이유 | 선택한 전략 | 다시 확인할 시점 | 이후 작업에서 확인한 변화 |
|---|---|---|---|---|---|
| | | | | | |

기준 ID는 연결을 유지하되 한 개의 교사용 평가요소가 학생용 관찰 질문 여러 개로 풀리는 것은 허용한다. 이름과 문장을 문자 그대로 같게 강제하기보다 평가하는 의미가 같고 추적 가능해야 한다.

## 7. 후속 검증 입력과 통과 조건

**아래는 실행 제안이며 이번에 새 모델로 실행한 테스트가 아니다.** 같은 모델에 정답을 알려주고 문구만 재현하게 하지 말고, 실제 요청과 필요한 원자료로 결과를 검사한다. 외부 환경·실제 교실 검증도 별도로 표시한다.

| 입력 사례 | 통과 조건 |
|---|---|
| 기존 최종 점수 집합을 유지해 표를 개선해 달라는 요청 | 최대점·최저점·가능한 점수 단계가 보존되거나 변경안으로 명시됨. 미관찰·미제출이 낮은 성취와 구분됨 |
| 자료로 원인을 설명하는 목표만 주고 4수준을 요청 | 최고 칸에 미확인된 반론·한계·추가 조사 능력을 자동 추가하지 않음 |
| 처음부터 기준을 충족해 수정하지 않았지만 유지 이유를 설명한 가상 과정 기록 | 변경량 자체로 낮은 성찰이라 단정하지 않고, 루브릭의 해당 성공 경로를 점검함 |
| 체육 기능 또는 작업 안전 수행의 과제와 기준 설계 요청 | 목표 밖 설명 글을 필수 최고점 조건으로 붙이지 않음 |
| 학생들이 동료평가를 처음 한다는 활용 요청 | 기준 이해·자기평가 연습·동료평가 규범·수정 기회가 설계됨. 친구 제안의 채택을 강제하지 않음 |
| 수업 활용 양식 요청 | 작성 칸뿐 아니라 실제 수정/유지, 재확인, 교사의 다음 조치가 연결됨 |
| 같은 목표의 반복 평가를 어떻게 종합할지 묻는 요청 | 중앙값만 기계적으로 권하지 않고 척도·최근성·양상·경계 처리·학교 규정을 구분함 |
| 서로 다른 목표를 측정한 초기·최근 과제의 처리 방법 요청 | 단순히 최근 결과가 이전 결과를 대체한다고 안내하지 않음 |
| 성취기준 원문은 있으나 MCP는 없는 환경의 생성 요청 | 제공 원문으로 진행하고 미확인 상태를 정확히 표시함. 코드를 만들어 내지 않음 |
| 실제 학생 작업을 주며 점수를 매겨 달라는 요청 | 해당 스킬의 범위에 따라 루브릭 진단으로 제한하고 학생 점수·등급을 산출하지 않음 |

학습 효과를 보려면 후속 교실 사용에서 학생이 기준을 설명할 수 있었는지, 자기 작업의 근거를 찾았는지, 피드백 후 같은 목표의 수행이 어떻게 달라졌는지를 관찰해야 한다. 문서 구조 검사나 사례 개수만으로 그 결과를 대신할 수 없다.
