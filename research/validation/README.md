# 실제 평가계획으로 한 검증 (2026-09-07)

Rubric Creator 스킬의 "기존 표 개선" 절차를 **실제 고등학교 평가계획서의 채점기준표** 5건에 적용했다. 학교는 익명화했다.

## 방법

1. **자료 수집**: 학교알리미 공시 항목 4-가 「교과별(학년별) 교수·학습 및 평가계획에 관한 사항」의 2026학년도 1학기 첨부문서. 세션의 SchoolInfo MCP 연결이 실패해(원격 서버 주소 이전) 같은 서버의 새 주소로 파일 목록을 확인하고, 첨부파일은 학교알리미 웹 요청을 재현한 스크립트로 직접 내려받았다. PDF는 로컬 파싱, HWP는 claw-hwp로 변환.
2. **사례 선정**: 국·영·수·사·과 다섯 교과, 다섯 시도(가·나·다·라·마 지역으로 익명화). 각 시도에서 일반계고를 무작위로 28곳 표집해 과목별 파일이 분리된 학교 가운데 채점기준표가 문서에 실제로 있는 것을 골랐다.
3. **절차**: 스킬의 `references/revise-rubric.md` 순서대로 — 교육과정 판본·성취기준 확인(MCP) → 원본 기록 → 점검표 11문항 진단 → 요소별 처리(유지/수정/통합/체크리스트 이동) → 총점·단계 유지 개선안 → 학생용 성공 기준 → 교사 결정 사항.
4. **하지 않은 것**: 교사 인터뷰, 학생 산출물 채점, 실제 문항 열람. 진단은 문서에 적힌 범위에서만 했고 확인이 필요한 것은 "미확인"으로 남겼다.

## 익명화

학교명·교사명·주소·학교 식별코드는 공개 문서에 쓰지 않는다. 사례 ID(가 지역 A고 …)와 실제 출처의 대응은 `research/private/validation/case-map.json`에만 있다. 원본 파일과 추출 텍스트도 `research/private/validation/downloads/`에만 둔다. 평가계획서는 공시 자료이지만, 특정 학교·교사의 채점 관행을 공개적으로 비평하는 형태가 되지 않도록 했다.

## 다섯 사례를 가로지르는 발견

**1. 개수 세기가 기본 문법이다.** 다섯 사례 모두에 "N개 중 M개 충족 → 점수" 또는 "자료 2건·출처 2개" 형식이 있다. 국어(6개 기준 충족 개수), 영어(자료·출처·항목 수), 사회(관점 4개 중 몇 개), 과학(구조 4개 중 몇 개, 버튼 4개 중 몇 개). 이 형식은 채점이 빠르고 이의 제기에 강하지만, 성취기준의 핵심(타당성·통합·연결·이해)을 재지 않는다. 개선안은 모두 **개수 → 같은 축의 질**로 바꾸되 총점·단계 수는 유지했다.

**2. 학교는 이미 좋은 기술을 갖고 있다.** 국어(성취수준별 수행 특성 A–E), 영어(같은 문서의 다른 과제), 수학(성취기준별 성취수준)에는 질적 기술이 있는데, 정작 점수를 정하는 표는 개수나 평정 척도다. 개선의 절반은 새로 쓰는 것이 아니라 **있는 기술을 채점표로 올리는 것**이었다.

**3. 지시 이행과 태도가 학업 점수에 섞인다.** 분량(국어·과학), 슬라이드 수·제출률(영어), 수업 태도·전자기기 사용(사회), 버튼 조작·색 강조(과학). 과학 사례는 약 40점이 이에 해당한다. 스킬은 이를 "제거"가 아니라 **체크리스트·별도 기록으로 분리**하고 사전 고지를 권했다.

**4. 과제명과 루브릭이 어긋난다.** 사회 사례의 과제명에 있는 "해결 방안 도출과 타당성 평가"를 재는 요소가 없었다. 영어 사례는 성취기준(영어 텍스트 파악)과 과제 언어(한글 초안, 자료 언어 미상)의 정렬이 문서만으로 확정되지 않았다. 스킬은 전자는 요소 신설을, 후자는 교사 확인을 제안했다.

**5. 교육과정 판본 확인이 실제로 필요하다.** 가 지역 A고 3학년 「화법과 작문」은 2015 개정 과목이며 2026학년도 고3에 맞다. 2022 개정 MCP에는 없으므로 성취기준을 `사용자 제공`으로 처리했다. 판본을 확인하지 않았다면 "코드가 없다"고 잘못 진단했을 것이다.

**6. 범용 칸의 문제(수학).** 세 문항이 모두 "오류 없음/오류 있음/부분/없음"이라는 같은 4칸을 써서, 전략이 틀린 답과 계산만 틀린 답이 구별되지 않았다. 문항마다 그 성취기준의 능력을 칸에 적는 것이 개선의 전부였다.

## 스킬 규칙이 작동한 지점과 한계

- **작동**: 점검표 11문항이 다섯 사례에서 각각 4–6개 항목을 잡아냈다. 총점·단계 유지 우선 규칙 덕에 모든 개선안이 학교 양식 안에 들어간다. "학생 채점 금지" 원칙은 시험할 학생 작업이 없어 발동하지 않았다.
- **한계**: 교사 인터뷰가 없어 정렬(과제 조건, 수업에서 가르친 것)은 대부분 "미확인"이다. 개선안의 기술은 실제 학생 작업으로 구별력을 점검하지 않았다. 다섯 사례 모두 초안이며, 교사가 경계 사례를 놓아 보고 고쳐야 한다(설계안 13절 E28은 미실시).
- **MCP 한계**: SchoolInfo 원격 MCP는 문서 변환 중 프록시 시간 초과(약 30초)로 502를 반환해 파일 목록 조회에만 쓸 수 있었다. 스킬 사용자 환경에서도 같은 문제가 날 수 있으므로, 평가계획서는 교사가 파일을 직접 주는 경로를 기본으로 두는 것이 안전하다.
