## 2. GRASPS가 백워드 설계 안에서 차지하는 자리

**GRASPS는 2단계(평가 증거 결정)의 도구다.** 백워드 설계는 1단계 바라는 결과(이해·핵심 질문·지식·기능) → 2단계 증거(어떤 수행이 그 이해를 입증하는가) → 3단계 학습 경험 순서로 간다. 2단계의 질문은 "무엇이 재미있을까"가 아니라 "무엇이 1단계의 증거가 되는가"다(146–151). 저자들은 흥미로운 프로젝트와 타당한 증거를 혼동하는 것을 가장 흔한 오류로 꼽는다(156, "Misconception Alert").

**GRASPS는 진정한(authentic) 수행과제의 특징을 설계 도구로 바꾼 것이다**(157). 진정한 과제는 다음 특징을 가진다(154).
1. 현실적 맥락 안에 있다.
2. 판단과 창의를 요구한다. 문제의 성격을 학생이 스스로 파악하고 계획을 세워야 한다.
3. 그 교과를 "한다". 배운 것을 재진술하는 대신 탐구·작업을 수행한다.
4. 어른이 직장·시민 생활에서 실제로 시험받는 상황을 재현한다. 제약, "잡음", 목적, 청중이 있다.
5. 지식·기능의 레퍼토리를 복합·다단계 과제에서 통합해 쓴다.
6. 연습·자료 참고·피드백·수정 기회가 있다. 과제와 평가 기준을 미리 안다("비밀 시험"이 아니다).

**연습(exercise)과 문제(problem)의 구분**(155–157, 그림 7.6): 연습은 단서가 주어지고 정답이 하나이며 "맞는 기법"을 알아보는 것이 목표다. 문제는 진술은 분명하지만 접근법 단서가 없고, 여러 접근이 가능하며, 청중·목적·기준이라는 경쟁 변수가 있고, 답보다 **접근과 해결의 정당화**가 증거가 된다.

**여섯 측면(six facets)**은 "어떤 종류의 증거가 필요한가"의 청사진이다(161–167): 설명, 해석, 적용, 관점, 공감, 자기지식. "정말 이해한 학생은 …할 수 있다"는 문장으로 필요한 수행을 도출한다. 특히 **설명(왜 그렇게 했는지, 근거는 무엇인지)은 다른 다섯 측면의 과제에도 항상 포함**되어야 한다(167). 답만 있고 이유가 없으면 이해의 증거로 불충분하다.

**핵심 질문 → GRASPS**(168): 핵심 질문을 먼저 논술형 시험 문항이라 가정하고, 그 질문을 더 진정한 방식으로 다루는 GRASPS 상황을 만들어 본다. **상황이 억지스러우면 GRASPS를 쓰지 말고 전통적 논술 프롬프트를 유지한다.** 모든 수행평가가 GRASPS일 필요는 없고, 주요 단원당 핵심 과제 하나 정도를 이렇게 만든다(158).

## 3. GRASPS 여섯 요소

저자 워크시트(2010, p.14)와 UbD 그림 7.7(159)의 문장 틀. 저자들은 "아이디어 시작점이며, **모든 빈칸을 채우려는 충동을 참으라**"고 명시한다.

| 요소 | 문장 틀 | 설계에서의 기능 |
|---|---|---|
| **G**oal 목표 | 당신의 과제는 … / 목표는 … / 문제(도전)는 … / 극복할 장애물은 … | 상황 안에서의 실제 목적. 학습목표가 아니라 **시나리오 안의 목표** |
| **R**ole 역할 | 당신은 … / 당신은 …을 요청받았다 / 당신의 일은 … | 학생이 맡는 입장. 현실의 직업·역할 |
| **A**udience 청중 | 고객은 … / 대상 청중은 … / 설득해야 할 사람은 … | 결과물을 받아 판단·결정하는 사람(실제 또는 가상) |
| **S**ituation 상황 | 당신이 처한 맥락은 … / 도전은 …을 다루는 것이다 | 제약·조건·"잡음". 판단이 필요한 이유 |
| **P**roduct/Performance & Purpose 산출물·수행·목적 | 당신은 …을 만들 것이다, …하기 위해 / …을 개발해야 한다, …하도록 | 무엇을 만드는가 **+ 왜**(목적이 붙어야 한다) |
| **S**tandards & Criteria 기준 | 당신의 수행은 …해야 한다 / 작업은 …로 판단된다 / 산출물은 다음 기준을 충족해야 한다 / 성공한 결과는 … | **학생에게 미리 공개되는 성공 기준. 루브릭의 평가요소와 같아야 한다** |

저자 예시(2010 pp.12–13; UbD 158, 160): M&M 포장 설계(수학, 포장 엔지니어 → 비용 절감 임원 설득), 지역 4일 투어 계획(사회, 관광청 인턴 → 외국 방문객), 세제 실험 설계(과학, 소비자 연구 과학자 → 잡지 검사부). 세 예시 모두 **역할이 교과의 실제 실무자**이고, **산출물에 근거·계산·이유 설명이 포함**되며, **S가 목표 도달의 질(비용 효과·부피 최대화·안전 / 변인 통제·절차 명료성)을 가리킨다.**

워크시트 pp.15–16에는 역할·청중 목록(약 100개)과 산출물 목록(글·말·시각 약 90개)이 있다. 산출물 목록의 단서: "학생 산출물·수행은 명시적 목적과 확인된 청중에 의해 틀 지워져야 한다."

## 4. 기준과 타당성 (8장): 루브릭과의 연결

- **기준은 목표에서 도출한다. 보기 쉬운 것에서 도출하지 않는다**(173). 각주가 많다고 높은 점수, 재치 있다고 이해했다고 추정, 화려하다고 효과적이라 판단하는 오류.
- **분석적 루브릭을 권한다**(174–175). 총체적 점수는 결함이 서로 다른 두 작업을 같게 보이게 한다.
- 시작점은 두 기준: **이해의 질**과 **수행의 질**. 필요하면 과정을 셋째로 추가(181).
- 여섯 측면별 기준어(그림 8.2, 177): 설명: 정확·일관·정당화·체계·예측 / 해석: 의미·통찰·중요·예시·조명 / 적용: 효과·효율·유창·적응·우아 / 관점: 신뢰·드러냄·통찰·타당·특이 / 공감: 민감·개방·수용·지각·재치 / 자기지식: 자각·메타인지·자기조정·성찰·현명.
- **기술어는 실제 학생 작업을 분류해 봐야 완성된다**(180). Arter & McTighe의 6단계(표본 수집 → 상·중·하 분류와 이유 → 특성 묶기 → 기술 → 적용·수정)는 Brookhart의 상향식과 같은 절차다.
- **평균 내지 말 것**(177): 이해는 시간에 따라 자라므로 초기와 최종을 평균하면 왜곡된다.

**타당성 자기점검**(184, 그림 8.5 187):
- 두 질문: (1) 학생이 이 과제를 잘 해내고도 목표한 이해를 보여 주지 못할 수 있는가? (2) 이해가 깊은 학생이 이 과제에서 못할 수 있는가? 하나라도 "그렇다"면 타당한 증거가 아니다.
- 일곱 항목(모두 "매우 낮음"이어야 함): 영리한 추측으로 / 배운 것을 그대로 옮겨서 / 열심히만 해서 / 예쁜 산출물로 / 타고난 언변으로 잘 할 수 있는가; 이해가 깊은데 과제가 목표와 무관해서 / 기준이 자의적이어서 못할 수 있는가.
- 같은 두 질문을 루브릭에도 적용(188): 기준을 충족하고도 이해가 없을 수 있는가? 기준을 못 채우고도 이해를 보일 수 있는가?

이 두 질문은 Brookhart의 "과제가 그 증거를 낼 기회를 주는가"와 같은 검사이고, DOK 정렬 점검과도 겹친다. 세 자료가 같은 곳을 가리킨다.

## 5. 실증 자료가 말하는 것

- Flores(2023): 필리핀 중등 수학교사 72명 설문. Goal은 "challenging", **Role·Audience·Situation·Product·Standards는 "very challenging"**. 교사 배경(성별·연차·학력)에 따른 차이 없음. → 교사에게 GRASPS 빈칸을 주는 것만으로는 부족하다. 역할·청중·상황을 **제안해 주는** 기능이 필요하다.
- Alvarez Llerena(2024): 에콰도르 EFL 학생 283명, 교사 16명이 2주 워크숍 후 3단원 설계. 학생들은 언어 능력·창의성·자율성 향상을 **인식**했다. 인식 조사이며 성취 효과 측정이 아니다.
- 두 연구 모두 한국 맥락이 아니고, GRASPS가 학습 성취를 높인다는 인과 근거는 아니다. DOK와 같은 수준으로 한계를 표시한다.

## 6. 스킬에 반영하는 방안

### 6.1 새 모드 "과제 재설계"

현재 스킬은 "정렬 점검"에서 과제가 증거를 못 내면 **보완을 제안하는 데서 멈춘다.** 이 지점에서 GRASPS로 과제를 다시 짜고, 그 과제의 S(기준)를 그대로 루브릭의 평가요소로 이어 가는 모드를 추가한다.

발동 조건:
- 교사가 "과제를 다시 짜 달라", "수행과제 만들어 달라", "더 실제적인 과제로" 요청
- 성취기준만 있고 과제가 없을 때(현재는 "과제 후보를 좁힌다"만 함)
- 정렬 점검에서 과제가 목표의 증거를 못 낼 때, 교사에게 재설계를 제안하고 동의 시 진입
- 타당성 자기점검 7항목에서 "가능성 높음"이 나올 때

### 6.2 절차

```
1단계 바라는 결과 정리
   성취기준 → 이 단원의 "이해"(일반화 문장 1–2개) → 핵심 질문(선택) → 지식·기능
   ※ 2022 개정 교육과정의 영역별 "핵심 아이디어"가 UbD의 영속적 이해에 가장 가깝다. 교사가 주거나 공식 문서에서 확인한 것만 쓴다.
2단계 필요한 증거
   "정말 이해한 학생은 …할 수 있다"를 여섯 측면 가운데 해당하는 것으로 2–4개 작성
   설명(근거·이유)은 항상 포함
   현재 과제가 있으면: 연습인가 문제인가 / 타당성 두 질문 / DOK 정렬
3단계 GRASPS 시나리오
   핵심 질문(또는 이해)을 논술 문항으로 먼저 써 보고 → 이를 더 진정하게 다루는 상황을 설계
   G·R·A·S·P·S 순서로 채우되 필요한 칸만; 역할·청중·산출물은 2–3안 제시하고 교사가 고름
   S(기준)는 목표 도달의 질을 가리키는 3–5개 문장 → 이것이 루브릭 평가요소의 씨앗
   억지스러우면 GRASPS를 포기하고 학술적 프롬프트 + 기준 공개로 설계
4단계 타당성 자기점검
   7항목 표를 채워 "가능성 높음"이 있으면 시나리오를 고친다
   모둠·자유 선택·집에서 하는 작업이 개인 증거를 흐리는지 확인
5단계 기존 루브릭 흐름으로 연결
   정렬표 → 평가요소(= S 기준) → 수준 기술 → 학생용 성공 기준 → 배점
```

### 6.3 산출물

1. **학생용 과제 안내문**(GRASPS 형식, 한 쪽): 목표·역할·청중·상황·산출물과 목적·성공 기준. 기준은 루브릭 평가요소와 같은 이름·같은 ID.
2. **교사용 설계 근거**: 1단계 정리, 필요한 증거(측면), 타당성 점검 결과, 원래 과제와 바뀐 점·이유.
3. **루브릭**(기존 출력).
4. 제출 조건 체크리스트(기존).

### 6.4 지킬 규칙 (새로 추가)

- **GRASPS를 강요하지 않는다.** 상황이 억지스럽거나 역할극이 목적을 가리면 전통적 프롬프트를 유지한다. 저자들이 직접 말한 경계다.
- **흥미 ≠ 증거.** 재미있는 프로젝트 제안 요청에도 "이 과제가 1단계의 증거를 내는가"를 먼저 묻는다.
- **역할·청중은 그 교과의 실제 실무·시민 생활에서 온다.** 장식용 역할(요리사가 분수 문제를 푼다)은 피한다. 특성화고는 직무에서 자연스럽게 나온다.
- **산출물에는 목적이 붙는다**("…을 만들어서 …하도록"). 형식만 있는 산출물 지시는 다시 쓴다.
- **S는 루브릭과 동일하다.** 과제 안내문의 기준과 루브릭 평가요소가 다르면 결함이다.
- **설명·정당화를 요구한다.** 산출물만 있고 이유가 없는 과제는 이해의 증거로 불충분하다.
- **원래 과제를 보존한다.** 재설계안은 원본과 나란히, 바뀐 이유와 함께.
- **한국 학교의 수행평가 조건**을 확인한다. 수업 시간 내 실시, 개인 평가, 공정성 요구가 있으면 실제 외부 청중 대신 가상 청중, 집 과제 대신 교실 내 단계로 조정한다.
- 학생 제출물 채점 금지 원칙은 그대로다.

### 6.7 확인이 필요한 것

- **핵심 아이디어 활용 여부.** 2022 개정 교육과정 각 교과 영역의 "핵심 아이디어"를 UbD의 이해로 쓰는 안은 논리적으로 맞지만, MCP 데이터에 포함되어 있는지 확인하지 않았다. 없으면 교사 제공 또는 공식 문서 확인으로 둔다.
- **한국어 번역 용어.** UbD 한국어판(강현석 외 역)의 공식 용어(예: "영속적 이해", "본질적 질문")를 스킬 용어로 쓸지, 교사에게 익숙한 말로 풀어 쓸지. 이번 조사에서는 한국어판을 읽지 않았다.
- **분량.** 과제 재설계까지 넣으면 SKILL.md가 길어진다. 모드 진입 시에만 `task-design.md`를 읽는 구조로 SKILL.md 증가를 20줄 이내로 억제한다.

## 7. 이번 조사의 한계

- UbD 2판은 제3자 사이트에 게시된 PDF를 연구용으로 읽었다. 스킬에는 원문·그림·예시 과제를 복제하지 않고 원리와 문장 틀(저자가 공개 배포하는 워크시트의 것)만 재구성한다.
- 7·8장만 읽었다. 1단계(이해·핵심 질문 작성법, 3–6장)와 3단계(WHERETO, 9장)는 읽지 않았다. 과제 재설계에 필요한 1단계 요소는 7장의 요약 수준에서 다뤘다.
- 한국 교육부·교육청의 백워드 설계 안내 자료는 확인하지 않았다.
- GRASPS의 학습 효과에 대한 인과 연구는 찾지 못했다.

## 8. 후속 확인 결과와 구현 (2026-09-07)

- **핵심 아이디어 데이터 여부**: 세 MCP 스냅샷(초등·중등·직업)의 `curriculum-standards.json`, `standard-texts.json`에 "핵심 아이디어" 필드·문자열이 없음을 확인했다. 스킬은 교사 제공 또는 교육과정 문서의 내용 체계 표 확인으로 두고, 없으면 성취기준에서 잠정 일반화를 쓰되 "잠정"으로 표시한다.
- **용어**: 사용자 지시에 따라 2022 개정 교육과정 문서를 따른다. 국어과 교육과정(교육부 고시 제2022-33호 별책5)에서 확인한 용어: 핵심 아이디어(41회), 내용 체계, 내용 요소, 지식⋅이해/과정⋅기능/가치⋅태도(가운뎃점은 U+22C5), 성취기준 해설, 성취기준 적용 시 고려 사항, 교수⋅학습의 방향/평가의 방향/평가 방법, 성취수준(117회), 수행 과정, 자기 평가/동료 평가(띄어쓰기). "영속적 이해", "본질적 질문", "핵심 질문", "루브릭"은 0회. 문서는 핵심 아이디어를 "영역의 학습을 통해 일반화할 수 있는 내용을 핵심적으로 진술한 것… 학습자들이 성취하기를 기대하는 결과"로 정의하며, 이는 UbD의 영속적 이해에 해당한다.
- **구현**: `rubric-creator/references/task-design.md` 신설, `SKILL.md`(범위·모드 표·인터뷰·정렬·출력·참고 파일·말하지 않을 것), `rubric-principles.md`(성공 기준 = 평가요소, 타당성 두 질문), `dok.md`(재설계 연결), `sources.md`(D절), `DESIGN.md`(모드 표, 검증 사례 E29–E35, 파일 구조) 갱신. `~/.claude/skills/`, `~/.codex/skills/`, `dist/rubric-creator.zip` 재배포.
